# 0.9.1 线上发布与自动升级验证

日期：2026-09-26（北京时间）。对应程序版本：0.9.1。

## 原因与修复

此前只交付了本地 0.9.1 程序，公共更新清单和下载地址仍为 0.8.2。因此旧版显示“已是最新版 v0.8.2”。

本次沿用现有静态服务和自动更新协议，完成了线上发布：

- [更新清单](https://acv.k-neco.com/tools/oopz-tactical-overlay/latest.json)现在指向 0.9.1 的固定版本文件。
- [原下载入口](https://acv.k-neco.com/tools/oopz-tactical-overlay/OopzTacticalOverlay.exe)已同步为 0.9.1。
- 文件大小：38,600,192 字节。
- SHA-256：`f6c0f7bef3474eca3635f45d14549467915717d4156cc6a453d63f459bfa5160`。
- 实际发布时间：2026-09-26 01:16:34 +08:00。
- 旧程序和旧清单已备份在公开目录之外；更新清单与下载入口均通过临时文件原子替换。
- 从公共 HTTPS 地址重新读取清单通过；用户 Windows 主机使用 Python 默认 HTTPS 验证也读取到了正确版本和校验值。

## 真实旧版升级

在隔离的 Windows 11 ARM64 虚拟机上运行原始 x64 发行包，使用独立设置目录，不连接 Oopz 频道。
旧包 SHA-256：`b8e2ac11bd72c360b19bedba8b4f34317b8c4fd02476ac2070115e1bd9891030`。

以下各项均通过：

1. 0.8.2 正常启动并显示旧版设置界面。
2. 旧版从真实公共地址自动下载 0.9.1，生成待更新记录，下载文件大小和 SHA-256 正确。
3. 下载完成时，正在运行的原程序仍是 0.8.2，未被强制重启或提前替换。
4. 正常退出再启动后，更新助手替换原文件，并自动打开 0.9.1 设置界面。
5. 待更新记录清除，没有生成更新错误记录；新文件 SHA-256 与线上清单一致。
6. 预设的字号、文字透明度、背景透明度、快捷键等设置完整保留。
7. 新版正常退出，F8/F9 均已释放。

## 测试环境说明

首次测试中，虚拟机的系统证书环境无法验证站点证书，旧版没有下载更新。独立 HTTPS 请求复现了 `CERTIFICATE_VERIFY_FAILED`；用户 Windows 主机使用默认信任环境访问正常。

复测仅向测试进程提供从 [Let's Encrypt 官方证书页面](https://letsencrypt.org/certificates/)获取的 ISRG Root X1，通过 `SSL_CERT_FILE` 使用。保留证书链与主机名验证，没有修改系统信任库，也没有关闭 HTTPS 验证。随后上述自动升级流程全部通过。

该证书的 SHA-256 指纹：`96bcec06264976f37460779acf28c5a7cfe8a3c0aae11a8ffcee05c0bddf08c6`。

## 使用方式

程序在启动时检查并下载更新。发布时已经打开的旧版需要先重启一次触发检查；出现“已下载，重启后更新”后，从托盘退出再打开原程序，完成替换。

本次修复的是发行渠道遗漏，没有更改自动更新协议或发布新的程序构建。后续发行遵循[发行与自动更新验收](releasing.md)。
